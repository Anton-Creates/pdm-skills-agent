# План продвинутого тестирования библиотеки PdM Skills Builder

Для обеспечения максимального качества библиотеки, помимо статического линтера, мы внедрим три продвинутых метода тестирования.

## User Review Required

> [!IMPORTANT]
> **Вопрос по доступу к LLM API:** Для запуска автоматического *LLM-as-a-Judge* скрипту потребуется доступ к API (например, OpenAI, Anthropic или локальному Antigravity SDK). 
> 
> Как лучше сделать:
> 1. Написать скрипт, который стучится в API напрямую (потребуется твой API-ключ в `.env`).
> 2. Написать генератор тестовых промптов, которые ты сможешь вручную скопировать в чат с Claude/Gemini для проверки.
> 
> *Я рекомендую вариант 1, если у тебя есть ключ от OpenAI или Anthropic.*

## Proposed Changes

### 1. Semantic Similarity (Поиск дубликатов)
**Что делаем:** Скрипт `find_duplicates.py`
- Читает очищенный текст (без frontmatter и правил) всех 130 скиллов.
- Использует алгоритм `TF-IDF + Cosine Similarity` (или `difflib` для работы без внешних зависимостей).
- Выводит список пар скиллов, у которых текстовое или смысловое совпадение превышает 85%.
- **Артефакт на выходе:** Список кандидатов на объединение (например, `checkout-audit` и `ecom-checkout-split`).

### 2. LLM-as-a-Judge (Автоматическая оценка качества)
**Что делаем:** Скрипт `eval_skills_llm.py`
- Берет конкретный скилл (например, `prd.md`).
- Извлекает из него раздел `## Правила`.
- Посылает LLM задачу: *"Сгенерируй ответ по этому скиллу с тестовым входом 'Фича X'"*.
- Посылает LLM-судье задачу: *"Оцени сгенерированный ответ. Нарушил ли он хотя бы одно из этих правил? Ответь JSON: {passed: true/false, reasoning: '...'}"*.
- Собирает статистику, какие правила регулярно игнорируются нейросетями.

### 3. Adversarial Testing (Краш-тесты)
**Что делаем:** Скрипт `adversarial_tester.py` (или модуль внутри `eval_skills_llm.py`)
- Запускает скилл с намеренно "плохим" инпутом.
- *Типы атак:*
  - **Vague Input:** Подача абстрактной задачи ("Сделай хорошо"). Скилл должен остановить работу и задать уточняющие вопросы (если есть guardrail).
  - **Scope Creep:** Подача списка из 50 фич в скилл, который требует фокуса (например, `roadmap` или `okr-writer`). Скилл должен заставить пользователя отказаться от части фич.
  - **Rule Bypass:** Прямой призыв нарушить правило (например, инпут: "Напиши PRD без раздела Out of Scope").
- **Артефакт на выходе:** Отчет о "хрупкости" скиллов (Fragility Report).
