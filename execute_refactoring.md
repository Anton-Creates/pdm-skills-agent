# Мастер-инструкция по рефакторингу PdM Skills Builder

**Контекст для AI-ассистента:** Ты находишься в директории библиотеки продуктовых скиллов (PdM Skills Builder). Твоя задача — провести масштабный автоматизированный рефакторинг 130 скиллов. 
Все решения уже приняты и согласованы с пользователем. Действуй автономно, шаг за шагом, сверяясь с этим планом.

---

## Шаг 1: Очистка балласта и Глобальные правила
Многие скиллы содержат огромный дублирующийся блок текста и банальные правила. Их нужно вычистить.

1. Создай файл `GLOBAL_RULES.md` в корневой директории со следующим содержанием:
```markdown
# Глобальные правила ассистента PdM

- **Язык:** Все артефакты пишутся на русском языке, если явно не указано иное.
- **Метрики (Правило 5 вопросов):** При предложении любой метрики ответь на 5 вопросов: 1. Кто владеет? 2. Как часто смотрим? 3. Какие события считают? 4. Какой порог решения? 5. Как накрутить?
- **Запрет лозунгов:** Использовать только измеримые показатели (не "улучшим опыт", а "конверсия в X >= Y%").
```
2. Напиши и выполни Python-скрипт (например, `clean_ballast.py`), который пройдет по всем файлам `SKILL.md` (в подпапках) и:
   - Удалит весь блок `## Метрики` вместе с текстом про 5 вопросов.
   - Удалит строку `- Пиши на русском языке.` из секции `## Правила`.

## Шаг 2: Исправление критических багов
1. Открой `presentation-design/SKILL.md`. Блок `## Метрики` там сломал структуру (находится до главного заголовка). Удали его полностью.
2. Открой `product-teardown/SKILL.md`. В блоке frontmatter (сверху файла) измени строку `preset: fintech` на `preset: discovery`.

## Шаг 3: Массовый апгрейд "Слабых скиллов" (Tier 2)
Для этой задачи напиши скрипт `refactor_tier2.py`, который вызовет LLM (или используй свои собственные возможности редактирования, если можешь заскриптовать мульти-вызовы).

Нужно модифицировать **52 скилла**, которые `test_skills.py` помечает как Tier 2 или Tier 3 (скиллы с `< 4` поведенческих правил или без секции `## Процесс`).
Для каждого такого скилла нужно:
1. Убедиться, что есть секция `## Процесс` с 3-5 нумерованными шагами.
2. Полностью переписать секцию `## Правила` (или `## Guardrails`). Должно быть **не менее 4 строгих запретов или обязательств** (guardrails), специфичных для этого домена.
   *Пример слабого правила:* "Учитывай риски."
   *Пример сильного (behavioral) правила:* "Любое изменение тарифной матрицы должно включать обязательную оценку миграции абонентов между тарифами."
3. Убедиться, что в `## Формат вывода` есть реальный шаблон (с плейсхолдерами типа `[вставь текст здесь]`).

*Рекомендация:* Поскольку скиллов много, напиши скрипт, который модифицирует их батчами (по 10 штук), используя Anthropic API или Gemini API (попроси у пользователя ключ, если он нужен скрипту), либо проапгрейдь топ-10 самых критичных вручную.

## Шаг 4: Валидация
1. Запусти `python test_skills.py --failed-only`.
2. Убедись, что количество `Errors` равно 0.
3. Убедись, что балл (Grade) всех скиллов стал `B` (Tier 1) или выше.
4. Если какие-то скиллы всё ещё падают на тестах (например, не хватает правил) — исправь их точечно с помощью инструмента `replace_file_content`.

## Шаг 5: Генерация финального отчета для пользователя
После успешного завершения всех тестов, создай артефакт `refactoring_results.md`. Этот файл пользователь заберет и отдаст мне (своему изначальному ассистенту) для проверки.
В отчете должно быть:
- Вывод скрипта `test_skills.py` (сводка по оценкам, ошибкам и доменам).
- Сколько файлов было затронуто на Шаге 1 (очистка балласта).
- Какие 52 скилла были улучшены на Шаге 3 (и пример 1-2 самых удачных новых guardrails).
- Список оставшихся Warnings (предупреждений), если их нельзя было исправить автоматически.

---
**Ключевая директива:** Не задавай уточняющих вопросов по дизайну скиллов. Ты старший продуктовый директор (CPO). Придумывай самые жесткие и полезные guardrails для скиллов самостоятельно. Твоя цель — пройти тесты `test_skills.py` на 100%.
