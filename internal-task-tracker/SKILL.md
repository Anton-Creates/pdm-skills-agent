# Внутренний тасктрекер и управление проектами (internal-task-tracker)

Спроектировать корпоративную систему ведения задач, спринтов и управления проектами (аналог Jira, Kaiten, YouTrack): доски, воркфлоу, контроль SLA, учет трудозатрат и отчетность.

## Процесс проектирования

1. **Спроектируй структуру пространств и сущностей:**
   - Иерархия: Пространство команды -> Проект -> Эпик -> Задача (Task) / Баг (Bug) -> Подзадача (Subtask).
   - Типы отображения: Канбан-доски (Flow), Scrum-доски со спринтами и бэклогом, таймлайн / диаграмма Ганта.

2. **Спроектируй конструктор рабочих процессов (Workflow Builder):**
   - Настраиваемые статусы (Бэклог -> В работе -> Код-ревью -> Тестирование -> Готово).
   - Правила переходов (Transitions), обязательные поля при смене статуса (причина отказа, ссылка на MR).
   - Автоматизации: автоназначение исполнителя, смена родительского статуса, уведомления в корпоративный мессенджер.

3. **Спроектируй контроль SLA и учет трудозатрат (Time Tracking & SLA):**
   - Таймеры SLA на этапах: время первой реакции, предельное время нахождение в статусе.
   - Списание трудозатрат (Log Work) с привязкой к статьям бюджета проектов.
   - Цветовая индикация просроченных задач и предупреждающие алерты.

4. **Опиши аналитику и проектные отчеты:**
   - Velocity команд, Burn-down чарты спринтов, распределение времени по типам задач (Feature / Bug / TechDebt).
   - Cumulative Flow Diagram (CFD) для выявления узких мест в воронке разработки.

5. **Сформулируй метрики эффективности работы команд:**
   - Обязательно ответь на 5 вопросов для каждой метрики.

## Формат вывода

```markdown
# Спецификация корпоративного тасктрекера: [Название компании / Проекта]

## 1. Иерархия сущностей и типы досок
- **Основные типы задач:** Epic, Story, Task, Bug, Incident.
- **Режимы досок:** Scrum со спринтерским бэклогом, Канбан с WIP-лимитами (ограничение задач в работе).

## 2. Модель жизненного цикла задачи (Workflow)
| Статус | Допустимые переходы | Обязательные действия |
| :--- | :--- | :--- |
| To Do | In Progress | Назначение ответственного исполнителя |
| In Progress | Code Review, Blocked | Указание ссылки на Pull Request / Причины блокера |
| Testing | Done, In Progress | Заполнение тестового отчета / Возврат с комментарием |

## 3. Модуль учета времени и SLA
- **SLA по инцидентам:** критические баги: реакция 15 мин, решение 4 часа.
- **Time Logging:** списание времени с возможностью интеграции с git-коммитами.

## 4. Метрики эффективности
- **Cycle Time:** среднее время выполнения задачи от статуса "In Progress" до "Done".
- **Lead Time:** полное время от создания задачи в бэклоге до релиза.
- **% соблюдения SLA:** доля задач, выполненных в регламентный срок.
- **WIP Discipline:** соблюдение лимитов параллельных задач на разработчика.
```

## Правила

- Фокусируйся на прозрачности процессов и удобстве ежедневной работы команд.
- Не используй длинные тире. Заменяй их на двоеточия, точки или дефисы.
- Каждая метрика должна пройти проверку по правилу 5 вопросов.
